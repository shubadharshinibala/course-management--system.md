REST API reference

This is the contract the frontend follows when talking to the backend. Use this table directly in your project report's API documentation section.

POST
/api/courses/
Create a new course record. Returns the created course with a generated id. 400 if validation fails or the course code already exists.
GET
/api/courses/
Return the list of all courses. Supports optional ?search= and ?department= query parameters.
GET
/api/courses/{id}/
Return a single course by its ID. 404 if the ID does not exist.
PUT
/api/courses/{id}/
Update an existing course. Full validation is re-run server-side. 404 if the ID does not exist.
DELETE
/api/courses/{id}/
Remove a course record permanently. 404 if the ID does not exist.
Validation rules enforced (client + server)
  • Course code — required, unique across the catalog, alphanumeric.
  • Course name, instructor, department, semester — required, cannot be empty.
  • Credits — required integer between 1 and 6.
  • Total seats — required integer between 1 and 500.
  • Enrolled count — optional integer, cannot exceed total seats.
